### 통합 시험 — 실행한 것과 대체한 경계

- 실행: `runCollectJob`(실제 HTTP 로 테스트가 띄운 로컬 목록 서버를 읽음 · 해석 · 정규화 · 드리프트 판정 · 저장), `evaluateCollectionViews`(표·REST·MCP 와 같은 판정), `runDeliverJob`(실제 웹훅 채널이 테스트가 띄운 로컬 수신 서버로 POST)
- 대체: 큐(BullMQ·Redis) — enqueue 를 가로채 같은 잡 함수를 직접 실행 · 채널 등록 — 워커 기동이 하는 `registerDeliverer` 를 테스트가 같은 방식으로 · 사설 주소 차단 — `ALLOW_PRIVATE_HOSTS=true` 로 로컬 서버만 허용
- 외부 사이트·실제 LLM: 호출하지 않았다 (추출 규칙은 사람이 적은 것)

## 3. 수정 전 버그 재현 (같은 테스트로)

- 시각 정렬을 밀리초로 자르기 전 식으로 되돌리면 `query.db.test.ts` 가 실패한다 — **기본 정렬에서 230개 중 44개만** 나오고, 오름차순 시각 정렬은 같은 행이 반복돼 1,400개가 나온다. REST·MCP 의 기본 정렬 페이지 이동에 있던 실제 결함이다.
- 깨진 뷰(사라진 칸)를 워커가 그대로 평가하던 결함 — 통합 시험 1회차가 "평가하지 않음(skipped) · 알림 0" 을 확인한다.

## 4. 빌드된 웹 앱 스모크 (테스트 DB 에 붙여 `next start`)

로그인 미설정(데모 — 모두 주인으로 취급) 상태. 14개 요청 전부 기대 문자열·상태 코드 확인:
표 첫 페이지(전체 240 · 다음 50개) · 저장된 뷰(상대 날짜가 **오늘** 기준으로 풀려 0건) · 검색+정렬 · 옛 커서 → "처음부터" 안내 · 모르는 파라미터 → 문제 카드 · 없는 뷰 · 필터 바에 칸 없는 조건 칩 · 뷰 화면 · 연결 화면(unlisted: 키 없이 · private: 헤더 안내·키 만들기) · 설정 화면(공유 안내) · REST 200/400/401.
로그에 `[auth][error] MissingSecret` 이 찍힌다 — `.env` 에 `AUTH_SECRET` 이 없는 기존 환경 문제이고 페이지는 200 으로 그려졌다.

## 5. 브라우저 시험 (`apps/web/e2e/table.e2e.ts` · ADR A51)

빌드한 앱(`next start`)을 테스트 DB 에 붙여 임의 포트로 띄우고 Playwright Chromium 으로 누른다 (7개 통과):
첫 페이지(전체 240 중 1–50) · **열 끌기**(주소 `cols` 기록 → 새로고침 후에도 순서 유지) · **열 고르기**(끄기 → 열 초기화) ·
**정렬 머리글**(서버 정렬 — 1,000원부터) → **다음 50개**(51–100) → **뒤로 가기**(1–50 복원) · **전체 검색**(200번째 너머까지 10건) ·
**새 뷰 저장**(검색어·정렬·열까지 DB 에 그대로, 그 뷰 주소로 이동·칩 생성) · **덮어쓰기**(slug 유지, 뷰 개수 그대로).
대체한 것: 첫 방문 둘러보기는 "건너뛰기" 를 누르고 시작, 로그인은 데모 모드(모두 주인 — 멤버 제한은 `views.db.test.ts` 가 본다).
이 시험이 잡은 결함 하나를 고쳤다 — 열 고르기 체크박스가 서버가 다시 그릴 때까지 눌러도 그대로 보였다(지금은 바로 반영).

### lint 가 짚은 기존 코드 고침 — 같은 동작인지 브라우저로 확인 (`e2e/flows.e2e.ts`, 4개)

| 고친 곳 | 무엇을 | 확인 |
|---|---|---|
| `tour/tour.tsx` | 자기 자신을 부르는 재귀를 안쪽 함수로 · 시작을 effect 본문 대신 다음 프레임에 | 처음 오면 뜨고 · 건너뛰면 닫히고 · 새로고침해도 다시 안 뜬다 |

| `create-flow.tsx` | 단계 연출 초기화를 **제출 이벤트**로 · 새 미리보기 때 편집 상태 맞추기를 렌더 중 비교로 | 워커 자리에 같은 계약의 로컬 서버를 세워 미리보기 두 번: 다시 누르면 첫 단계부터 · 지운 열·고친 이름이 새 미리보기로 초기화 |

`create-flow` 는 처음엔 초기화를 액션 함수 안에 두었는데, React 19 에서 액션 안의 상태 변경은 액션이 끝날 때까지 화면에 안 나온다 — **브라우저 시험이 그 회귀를 잡아** 제출 이벤트로 옮겼다.
대체한 경계: 컬렉션 만들기의 워커(사이트 살펴보기·LLM) → 같은 계약(POST `/internal/preview` · Bearer 토큰 · 같은 응답 모양)의 로컬 서버.

## 6. 하지 못한 검증

- **로그인한 실제 사용자로 화면 접근**: Google OAuth 자격증명이 없어 하지 못했다. 같은 판정 함수(`resolveAccessFor`)를 행위자를 직접 주어 시험했다.
- **실제 MCP 커넥터 앱**(Claude 등)에서의 연결: 하지 않았다. 공식 SDK 클라이언트로 실제 HTTP 연결을 시험했다.
- **개발 DB 마이그레이션**: `0006_watery_gambit.sql`(null 허용 컬럼 4개 추가)을 개발 DB 에 적용하지 않았다. 앱을 띄우기 전에 `pnpm db:migrate` 가 필요하다.
